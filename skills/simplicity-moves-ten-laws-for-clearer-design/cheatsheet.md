# Cheatsheet

Imperative decision rules from the source, grouped by category. Each is the kind of sentence you would write on an index card.

## design

- If a feature isn’t used, remove it.
- Make things smaller or lighter to lower user expectations.
- Hide complexity behind a simple interface that appears only when needed.
- Add real or perceived quality (better materials, clear signals) when you remove features.
- Sort items into piles, label each pile, integrate similar piles, prioritize the vital few.
- Use the tab key to turn a messy list into a clean table.
- Squint to see whether elements visually group into a whole.
- Remember that simplicity needs complexity to be meaningful; keep a contrasting element.
- Pay attention to the periphery: remove distractions, use whitespace, frame the center.
- Add warmth, joy, or curiosity through color, texture, sound, or micro‑interactions.
- Make every interaction behave the same way every time to build trust.
- Show progress or status honestly; admit limits rather than hiding failures.
- Accept that some complexity cannot be removed; design stages and defaults to manage it.
- Subtract the obvious elements, then add back only what is truly meaningful to the user.

## process

- Remove steps or replace choice with randomness to shrink time needed.
- Hide the passage of time by removing clocks or showing a smooth progress bar.
- Embody time with numerical countdowns, filling bars, or styling that suggests speed.

## general

- Learn by mastering the basics and repeating them often.
- Avoid overwhelming beginners with advanced features; start simple.
- Inspire learners with concrete examples of what they can achieve.
- Use relate‑translate‑surprise: connect to prior knowledge, show a mapping, add a surprise.
