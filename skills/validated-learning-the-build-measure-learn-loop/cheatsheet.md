# Cheatsheet

Imperative decision rules from the source, grouped by category. Each is the kind of sentence you would write on an index card.

## design

- Before you ship the next feature, name the assumption it tests and how you would know if it were wrong.
- Don't fall in love with your initial product idea; be willing to change course based on customer feedback.

## product

- Don't build features just because you *could*. Build them because you *should* – based on validated learning.

## general

- If a metric isn’t driving action, it’s a vanity metric. Focus on metrics that tell you what to do next.
- Measure everything, but don’t get bogged down in analysis paralysis. Focus on actionable insights.

## argument

- A pivot isn't failure; it's a strategic course correction based on new information.

## code

- Always design experiments to test your riskiest assumptions – the ones that, if wrong, would sink your startup.

## process

- Regularly review your assumptions and validate them with experiments – it's the only way to build a sustainable business.
