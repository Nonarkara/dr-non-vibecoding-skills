# Composition brief — decisions before CSS

Copy the useful parts into the project's existing design contract. Delete prompts
that do not apply; do not ship an empty form as evidence. This is original Dr Non
method material. Read the [source/adaptation guide](../references/ruttl-composition.md).

## The person and the work

- Person, situation, access needs and language:
- Task they came to finish; what success means to them:
- Actual content, routes, interactions and exports to conserve:
- Design Read specific to this product; named reference and why it applies:

## What wins, what supports it

- First thing noticed, second thing understood, third available action:
- Dominant subject and the area its job requires:
- Grouping relationships; shared edges; purpose of quiet space:
- Intentional imbalance and how its visual weight resolves:
- House typography roles, prose measure and script coverage:
- Palette roles/proportions; signal colors that must not be repurposed:
- Content-sized controls and usable hit areas; compact navigation:

## Two genuinely different arrangements

- A: order, adjacency and reading path using real content:
- B: different order, adjacency or reading path with the same content:
- Which task evidence favors the selected arrangement; what was rejected:
- Stable navigation/state rules across pages; content-driven variation within them:
- What would stop making sense if another product's name/content replaced ours:

## Promises and edge states

- Main action: visible verb + object; destination/result; recovery:
- Deep-link orientation and return path; browser-back behavior:
- Loading, empty/no-match, error, cancellation and disabled states:
- Long labels, Thai/Chinese facts, font failure, focus and text enlargement:
- Font/media/JavaScript budget and test device/network conditions:

## Evidence, not a score

| Claim | Check or observed task | Evidence | Passed / failed / unverified |
|---|---|---|---|
| Clear hierarchy and balanced grouping | Independent review of actual pixels | | |
| Content survives the narrow view | 1440 / 1024 / 390 screenshots; 320 reflow | | |
| Main task works | Pointer, keyboard, touch; result and recovery | | |
| Words communicate | Comprehension and fluent-language review where needed | | |
| Useful under constraints | Measured routes; stated device/network; field vs lab | | |
| Difference helps | One changed relationship; observed task outcome | | |

- Independent reviewer, actual observations and resulting revisions:
- Real first-time/older-reader walkthrough: performed or still unverified:
- Remaining blockers and preserved features checked after the change:

Do not invent praise, measurements or completion. Do not turn this into a
human-authorship score. An automated integrity check cannot clear the visual rows.
