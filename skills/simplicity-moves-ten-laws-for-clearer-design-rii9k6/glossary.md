# Glossary

Terms and named ideas from the source, anchored to the chapter that explains them.

| Term | Definition | Chapter |
| --- | --- | --- |
| **reduction** | Removing or lessening functionality to approach simplicity. | ch01 |
| **shrink** | Making an object physically smaller or visually lighter to lower expectations. | ch01 |
| **hide** | Concealing complexity behind menus, doors, or gestures that appear only when needed. | ch01 |
| **embody** | Adding real or perceived quality (materials, craftsmanship, signals) to compensate for removed features. | ch01 |
| **slip** | A four‑step organizing method: sort, label, integrate, prioritize. | ch02 |
| **sort** | Writing items on notes and moving them to find natural groupings. | ch02 |
| **label** | Giving each group a name, code, or color for identification. | ch02 |
| **integrate** | Merging similar groups to reduce the total number of categories. | ch02 |
| **prioritize** | Selecting the vital few items to receive top‑level attention. | ch02 |
| **tab** | Using the tab key to align information into rows and columns for visual order. | ch02 |
| **gestalt** | The mind’s tendency to see a whole made of parts, used to create visual groupings. | ch02 |
| **progress bar** | A visual indicator that shows how much of a wait has elapsed, making time feel shorter. | ch03 |
| **styling** | Adding visual cues (fins, streamlined shapes) that suggest speed without changing actual performance. | ch03 |
| **relate‑translate‑surprise** | A teaching pattern: connect new idea to prior knowledge, show a tangible mapping, then add an unexpected delight. | ch04 |
| **desktop metaphor** | A design that maps computer files to physical desk objects like folders and trash cans. | ch04 |
| **difference** | The necessary interplay between simplicity and complexity where each defines the other. | ch05 |
| **context** | The periphery or surroundings that influence how simple a central element feels. | ch06 |
| **emotion** | Positive feeling evoked by design that increases perceived simplicity. | ch07 |
| **trust** | Confidence that a design will behave predictably and reliably. | ch08 |
| **failure** | Inherent complexity that cannot be removed and must be accommodated. | ch09 |
| **the one** | The core simplicity move: subtract the obvious, add the meaningful. | ch10 |
