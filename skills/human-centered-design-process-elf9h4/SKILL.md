## When to load this skill

A practical skill set for AI agents that need to run a full human‑centered design (HCD) cycle: discover people, frame the problem, generate ideas, prototype, test, and iterate while embodying the five core mindsets. Load this skill whenever a design project, discovery phase, or method selection is required.

## Core principles

- Empathy is the only reliable way to uncover real needs; designers must listen before they solve.
- Optimism means assuming a solution exists and using constraints as creative prompts.
- Embracing ambiguity lets teams explore many ideas before committing to any single direction.
- Iteration is mandatory because the first solution is almost never the final one.
- Learning from failure accelerates progress; each test should produce concrete feedback.
- Design should be grounded in the people you serve, not in abstract assumptions.
- Minimum lovable solutions win adoption faster than merely functional prototypes.
- Not every problem is a design problem; match the method to the type of challenge.

## Frame Challenge

**When to use:** When a project starts with a vague problem statement.

**Recipe:**

1. Write a one‑sentence draft question.
2. Apply the impact, solution variety, and constraint filters.
3. Revise until five distinct solutions can be listed in five minutes.
4. Convert the final wording to a "How might we…" format.

**Chapter:** ch03

---

## Conduct Effective Interview

**When to use:** When gathering first‑hand insights from users.

**Recipe:**

1. Select 2‑3 team members with defined roles (interviewer, note‑taker, photographer).
2. Prepare a flexible guide that starts with broad life questions.
3. Interview in the participant’s own environment whenever possible.
4. Record verbatim quotes, observe body language, and capture photos with consent.

**Chapter:** ch04

---

## Use Extremes and Mainstreams

**When to use:** When you need a rich set of perspectives for ideation.

**Recipe:**

1. List key demographic dimensions (age, gender, income, location).
2. Identify at least one extreme user on each dimension and a representative mainstream group.
3. Recruit participants using the checklist and track them in a spreadsheet.
4. Interview each group, noting unique needs and surprising behaviors.

**Chapter:** ch05

---

## Iterative Prototype Loop

**When to use:** After an insight has been turned into a low‑fi prototype.

**Recipe:**

1. Build a paper or cardboard version of the idea.
2. Run a usability test with a single participant, noting success and friction.
3. Extract three actionable insights and prioritize by impact.
4. Update the prototype and repeat until the solution feels both functional and desirable.

**Chapter:** ch07

---

## Conversation Starter Workshop

**When to use:** When you need to spark creative thinking in a community.

**Recipe:**

1. Define a central theme (e.g., savings, sanitation).
2. Create 8‑12 absurd or simple prompts related to the theme.
3. Present the prompts to participants and ask for immediate reactions.
4. Follow each reaction with open‑ended questions to dig deeper.

**Chapter:** ch06

---

## Analogous Inspiration Scan

**When to use:** When you feel stuck on a design problem and need fresh perspectives.

**Recipe:**

1. List the behaviors or emotions you want to understand.
2. Identify unrelated settings where those behaviors appear (e.g., coffee shop queues).
3. Observe the analogous setting and note design cues.
4. Translate the most relevant cues back to your own challenge.

**Chapter:** ch06

---

## Guided Tour Observation

**When to use:** When you need spatial or routine context about a user.

**Recipe:**

1. Arrange a home or workplace tour with the participant’s consent.
2. Bring two team members: one to ask questions, one to take notes and photos.
3. Record details about layout, objects, rituals, and any contradictions.
4. Debrief with the participant to clarify observations.

**Chapter:** ch04

---

## Method Selection Decision Tree

**When to use:** When deciding whether to apply HCD or another discipline.

**Recipe:**

1. Ask: "Do we need to understand motivations?" If yes, continue with HCD.
2. If no, ask whether the barrier is cost, logistics, or regulation.
3. Match the barrier to the appropriate discipline (business analysis, supply‑chain, policy).
4. Select the most suitable HCD method based on the identified insight gap.

**Chapter:** ch09

---

## Pilot Validation Loop

**When to use:** When moving from a minimum lovable prototype to a scalable product.

**Recipe:**

1. Deploy the prototype to a small, representative user group.
2. Collect adoption, retention, and impact metrics over a set period.
3. Hold a stakeholder review to align on results and next steps.
4. Create a handoff package with research artifacts, design specs, and testing protocol.

**Chapter:** ch10

## Cheatsheet

# Cheatsheet

Imperative decision rules from the source, grouped by category. Each is the kind of sentence you would write on an index card.

## process

- Start every project by writing a one‑sentence "How might we" question.
- If a problem is about cost or logistics, skip HCD and run a business analysis.
- Keep the team size under five during field immersion to stay agile.
- Document every decision on a Kanban board to keep the iteration visible.

## design

- If you cannot list five solutions in five minutes, reframe the challenge.
- Run a quick card sort to surface priority needs before ideation.
- Always end a session by asking: "What would make this easier for you?"
- When stuck, look for analogous inspiration in an unrelated industry.

## research

- Interview in the participant’s own space whenever possible.
- Record verbatim quotes; never paraphrase during note‑taking.
- Include at least one extreme user in every interview batch.
- When you hear a surprising insight, pause the session and explore it fully.
- If participants refuse to answer, change the method—not the question.

## iteration

- When a prototype fails, note three concrete lessons before redesigning.

## code

- Use paper prototypes before any digital mock‑up.

## general

- Treat every test as a data point; never rely on gut feeling.

## product

- Validate a solution with a pilot before committing resources to scale.
- If a prototype feels merely functional, add an emotional element to reach minimum lovable.

## mindset

- Use optimism to reframe constraints as design prompts.
- Never assume a solution; always return to the user’s words.
