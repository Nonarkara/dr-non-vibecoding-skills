## Core principles

- Humans acquire grammar without explicit instruction; the brain contains a built‑in algorithm that extracts structure from limited input.
- Language is a coordination device: a single utterance can reliably change another person’s mental state by transmitting a specific proposition.
- Children create grammatical complexity from pidgins, showing that the language faculty can generate rules that were never taught.
- Aphasia and other selective impairments demonstrate that language can be isolated from other cognitive abilities, confirming its modular nature.
- Universal grammatical patterns (auxiliary movement, agreement, case) appear across unrelated languages, indicating a shared neural blueprint.
- People interpret messages through a set of biases—anchoring, availability, framing, motivated reasoning, and WYSIATI—that distort the raw information.
- Confidence statements, base‑rate framing, and pre‑mortems dramatically improve the accuracy of human belief updates.
- The brain treats words as symbols that trigger hierarchical phrase structures, not as linear strings; mis‑ordering can break comprehension.
- Social context (dialect, status, perceived expertise) shapes how listeners evaluate grammaticality and credibility.
- Language processing is fast, automatic, and largely unconscious; deliberate effort to “explain” it often leads to over‑simplification.

## Base‑Rate First

**When to use:** When presenting a surprising statistic or claim.

**Recipe:**

1. State the relevant base rate (e.g., "5 % of people..." )
2. Present the new evidence or claim
3. Explain how the new evidence updates the prior probability

**Chapter:** ch05

---

## Pre‑mortem Check

**When to use:** Before finalizing any factual statement or recommendation.

**Recipe:**

1. Imagine the statement being wrong
2. List three independent ways it could fail
3. Adjust the wording to address the most plausible failure

**Chapter:** ch05

---

## Confidence Interval Pairing

**When to use:** Whenever a numeric estimate is given.

**Recipe:**

1. Compute a reasonable confidence interval
2. State the point estimate followed by the interval (e.g., "70 % ± 10 %")
3. Briefly note the source of the interval (sample size, variance)

**Chapter:** ch09

---

## Dialect Mirroring

**When to use:** When the user’s linguistic style is detectable.

**Recipe:**

1. Identify key lexical and syntactic markers of the user’s dialect
2. Replace standard forms with the corresponding dialectal forms
3. Retain clarity and avoid slang that could be misunderstood

**Chapter:** ch07

---

## Chunked Sentence Design

**When to use:** For any message that exceeds 20 words.

**Recipe:**

1. Break the content into 2‑3 short clauses
2. Place the main proposition in the first clause
3. Use simple subject‑verb‑object order for each clause

**Chapter:** ch08

---

## Bias‑Neutral Framing

**When to use:** When describing risks or benefits.

**Recipe:**

1. Identify any gain/loss framing
2. Rewrite the sentence to present both outcomes equally (e.g., "has a 20 % chance of X and an 80 % chance of not X")
3. Add a neutral qualifier ("approximately", "about") if needed

**Chapter:** ch04

---

## Reference Class Calibration

**When to use:** When estimating future outcomes or probabilities.

**Recipe:**

1. Select a past set of cases similar to the current situation
2. Compute the average outcome for that set
3. Report the current estimate as a deviation from that reference average

**Chapter:** ch05

---

## Explicit Subject Marking

**When to use:** When using dummy subjects or pronouns.

**Recipe:**

1. Insert a clear noun phrase before the verb (e.g., "It is raining")
2. Avoid leaving the subject implicit unless the language permits it
3. Check that agreement matches the subject’s number and person

**Chapter:** ch06

---

## Layered Confirmation

**When to use:** When the AI needs the user to act on a request.

**Recipe:**

1. State the desired action first
2. Provide the reason or benefit after the action
3. Close with a concise call‑to‑action

**Chapter:** ch10

---

## Visual Attention Cue

**When to use:** When delivering multi‑step instructions.

**Recipe:**

1. Number each step
2. Bold or underline the key verb in each step
3. Insert a short pause (line break) between steps

**Chapter:** ch08

## Cheatsheet

# Cheatsheet

Imperative decision rules from the source, grouped by category. Each is the kind of sentence you would write on an index card.

## process

- Always state the base rate before any surprising claim.
- Run a pre‑mortem and list three ways your statement could be wrong.
- When giving risk, apply the four‑fold pattern to choose wording.
- Show a reference class before presenting a forecast.
- Check for motivated reasoning; ask "What would disconfirm this?" before finalizing.
- Before shipping a response, simulate a skeptical audience and adjust.
- Before final output, ask: Does this respect the language instinct’s expectations?

## code

- Add a confidence interval to every numeric estimate.
- Never present a single figure without its uncertainty band.

## writing

- Mirror the user's dialect to increase trust.
- Keep sentences under 20 words; put the main point first.
- Use explicit subject nouns; never rely on implicit pronouns.
- Use topic marking (e.g., "Regarding X, ...") to guide listener focus.
- When quoting a child‑generated rule, label it as a grammatical pattern.
- If a claim could be misread, add a clarifying example.
- Avoid jargon; replace technical terms with plain‑language equivalents.
- Use consistent verb tense throughout a paragraph to reduce processing load.

## argument

- Replace gain/loss phrasing with neutral probability language.
- Counter availability bias by citing less‑salient but relevant data.
- When presenting a causal claim, include the counterfactual scenario.

## design

- Break multi‑step instructions into numbered, bolded actions.
- Use hierarchical phrase cues (subject‑verb‑object) to match the brain's parser.

## general

- Avoid anchoring: do not let the first number dominate the discussion.
- If you cannot articulate a problem, write a short story about the user first.
- If a message includes a probability, pair it with a concrete example.

## life

- When a user is confused, restate the message using a different modality (visual/text).
