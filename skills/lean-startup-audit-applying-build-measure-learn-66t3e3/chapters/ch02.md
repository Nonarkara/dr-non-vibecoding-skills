# ch02 — Designing the Minimum Viable Product

> Explains how to create an MVP that is just enough to test the core hypothesis, avoiding over‑engineering and unnecessary features.

An MVP is the smallest set of features that can still answer the hypothesis question. The goal is to expose the product to real users as quickly as possible, collecting data on behavior rather than opinions. To design an MVP, start by isolating the *value proposition*—the single benefit you think users will pay for. Strip away everything else, keeping only the functionality needed to observe that benefit in action. Prototyping tools, low‑code platforms, or even paper mock‑ups can serve as MVPs if they let users interact with the core idea. The chapter walks through a step‑by‑step process: define the hypothesis, list the minimal features required to test it, build the simplest version, and launch to a targeted early‑adopter group. It also warns against the "feature creep" trap, where teams add polish before learning, and suggests using a "no‑frills" checklist to keep the MVP lean.
