# Glossary

Terms and named ideas from the source, anchored to the chapter that explains them.

| Term | Definition | Chapter |
| --- | --- | --- |
| **Participatory design** | Designing with future users by observing them, involving them in decisions, and iterating based on their feedback. | ch01 |
| **Usability test** | Watching real people attempt to use a prototype to discover where they struggle or succeed. | ch01 |
| **Iconic naming** | Using pictures that resemble real‑world objects to represent commands or files so users can recognize them at a glance. | ch02 |
| **Spatial metaphor** | Mapping interface elements onto familiar layouts like desks, filing cabinets, or rooms to leverage existing knowledge. | ch02 |
| **Modeless editor** | An editing mode where the same actions (e.g., typing, pointing) always have the same effect, eliminating mode‑switch errors. | ch03 |
| **Double‑click** | Two rapid mouse clicks in the same spot used to select a word (or three clicks for a sentence) without extra modifier keys. | ch04 |
| **Cut and paste** | A pair of commands that remove selected content to a buffer and then insert that buffer at the cursor location. | ch04 |
| **Cursor between characters** | Placing the insertion point in the gap between characters so typing adds new text after the left character, making the result obvious. | ch04 |
| **Smalltalk browser** | A three‑pane interface (classes, methods, code) with independent scroll bars that lets users browse and edit hierarchically. | ch05 |
| **Pull‑down menu** | A menu that remains hidden until the mouse selects its title, then appears vertically beneath it. | ch06 |
| **Menu bar** | A persistent horizontal strip, usually at the top of the screen, that holds the titles of pull‑down menus. | ch06 |
| **Affordance** | A perceivable property of an object that suggests how it can be used, such as a button’s shape indicating it can be pressed. | ch10 |
| **Feedback** | Immediate, perceptible response from the system that confirms an action has been recognized and executed. | ch10 |
| **Constraint‑driven design** | Using limits such as cost, hardware capability, or simplicity goals to focus design decisions on what truly matters to users. | ch07 |
| **Prototype‑test cycle** | A rapid loop where a builder creates a testable artifact by night and an evaluator observes real users with it by day, then feeds back observations. | ch08 |
| **Kinesthetic memory** | The unconscious ability to reach for a screen location (like a menu bar) without looking, built through repeated use. | ch06 |
| **WYSIWYG** | What You See Is What You Get—the principle that on‑screen appearance should match printed output. | ch07 |
| **Modal vs modeless** | Modal interfaces require users to be in a specific mode for actions to work; modeless interfaces keep actions consistent across contexts. | ch03 |
| **Desktop metaphor** | The concept of treating the computer screen as a virtual desk with folders, documents, and a trash can that users can manipulate directly. | ch10 |
| **Mouse button chording** | Using combinations of mouse button presses (e.g., double‑click) to issue different commands without adding physical buttons. | ch10 |
